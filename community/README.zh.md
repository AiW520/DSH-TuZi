# DSH-TuZi 社区版

[English](README.md) | 中文

DSH-TuZi 是基于 DeepSeek Harness 的独立社区发行版，不是 DeepSeek 或 TuZi 的官方版本。保留上游版权及许可声明。

社区版使用 `DSH-TuZi` 应用名称、`io.github.aiw520.dsh-tuzi` 应用标识、`dsh-tuzi://open` 协议和 `~/.dsh-tuzi` 数据目录。独立测试时可将 `DSH_TUZI_HOME` 设为绝对路径。继承的 `DSH_HOME` 不会将社区桌面版指向原版数据。Electron 设置保存于应用支持目录下的 `DSH-TuZi`，测试时可用 `--user-data-dir` 覆盖。社区版隐藏上游 `dsh` 命令安装入口，避免覆盖已有 CLI。

在仓库根目录构建 Apple Silicon 测试包：

```sh
DSH_TUZI_COMMUNITY=1 pnpm run package:desktop:mac:arm64:unsigned
```

此命令生成临时签名的测试应用，不是经过 Apple 公证的正式发行版。测试包关闭自动下载、安装及强制升级策略。签名发行版需要独立签名凭据以及安装验收。不得将凭据写入本目录、版本控制、安装产物或下载页。

模型能力识别保留供应商明确提供的元数据，使用内置目录中无歧义的完整模型标识，并在可用时读取 TuZi 的公开模型说明。模型目录同时声明音频或视频时，仍保留文本和图片能力。用户手动选择优先于检测建议；旧接口地址的异步返回会被丢弃。未知别名仍需手动选择或明确的真实请求验证，仅凭名称无法确定网关支持的请求格式。

pi-ai 默认允许流式连接空闲十分钟，并对临时错误最多重试八次。这不保证网关永不断线。宣布供应商稳定性前，仍需验收真实延迟、中断、取消及工具执行行为。

社区外壳关闭会话遥测及上游产品统计。本地和签名打包流程均保留社区版标题。

[云朵兔适配器](pet/README.zh.md) 复用 dsh-pet 的 MIT 代码，使用独立素材。它作为正常的可选配置组合包加载，共用应用内置的 Electron。移除组合包后重启不会重新添加，原生恢复流程也可将其禁用。独立的 `dsh-tuzi-brand` 组合包通过现有插槽提供侧边栏和会话品牌样式。

运行 `node community/tests/desktop-acceptance.mjs /absolute/path/to/DSH-TuZi`，指定已安装的可执行文件，可通过本地模拟供应商测试真实 Harness 会话、工具执行、桌宠状态及取消行为。这是应用集成证据，不等于真实供应商证据。[预览版验收说明](release-notes/README.zh.md) 分别记录两类结果。

`site/` 目录包含独立下载页。只发布通过验收的产物。页面读取 `releases.json`，只有通过验收的条目才显示安装包直链；清单为空或无法获取时，仍保留 GitHub 版本页面入口。每个发布条目必须包含平台、架构、版本、HTTPS 下载地址、字节大小、SHA-256 及签名状态。

下载页复用 `pet/assets/webm/` 中的六段动画，并在 `site/assets/` 中保存对应静态帧。更换桌宠素材时需同步这些副本。状态按钮仅供本地预览，不连接正在运行的 Harness 会话。动画在移出视口或页面隐藏时暂停，也可手动暂停；系统要求减少动态效果时默认显示静态图片。不支持视频播放时保留静态图片。

社区验收工作流在原生 Windows runner 上构建 Windows x64 安装包。未签名预览版不包含上游强制更新策略。安装程序使用社区版名称与云朵兔图标。完成 NSIS 安装后，工作流依次运行安装后的 Harness 和桌宠测试，并验证卸载保留社区数据目录，只有全部成功才生成安装包校验值与验收记录。在出现该记录之前，Windows 下载必须保持不可用。在临时 runner 上运行 `community/scripts/qualify-windows.ps1` 可重新执行安装验收。将 `DSH_COMMUNITY_EVIDENCE_DIR` 设为已有目录，可在其中保留隔离的测试记录；不设置时使用系统临时目录。

下载页识别操作系统，并支持手动选择系统与芯片。不会根据 Mac 浏览器标识猜测 Apple Silicon。缺少对应安装包时显示暂未发布，不将其他系统的安装包作为主下载按钮；手机与未知浏览器需要手动选择。`node community/tests/download-page.mjs` 使用 Playwright 检查这些状态；没有内置 Chromium 时，可设置 `DSH_TEST_BROWSER_CHANNEL=chrome` 使用已安装的 Chrome。

安装包继续托管在 GitHub Release。下载页对版本清单的临时故障最多请求三次，失败后提供手动重新加载。每个已验收下载都提供支持手动复制的链接、对应版本页面，以及可选的原生 curl 续传或 aria2 四连接命令。原生命令保留下载片段，对临时错误最多重试八次，通过 SHA-256 校验后才将临时文件改为安装包名称，并拒绝覆盖同名安装包。中断后可在同一目录再次执行；校验失败时需删除损坏的 `.part` 文件后重试。aria2 为可选工具，需用户事先安装。两种方式均使用 GitHub 原始版本链接，不经过公共代理，也不保存会过期的跳转地址。页面无法读取浏览器下载进度，不能保证带宽提升。`node --test community/tests/download-tools.mjs` 验证原生 curl 字节续传与损坏文件拒绝；Pages 工作流要求 Linux 与原生 Windows 检查通过后才部署。

社区更新提醒在启动 30 秒后及每六小时读取 Pages 上的小型版本清单，侧栏与应用菜单均提供手动检查。后台网络失败不弹窗，依次在 5、10、20、40、80、160、320 分钟后重试，随后每六小时重试；单次请求限时 20 秒，响应上限 256 KiB。检查不会下载安装包、安装、重启或中断任务。更新面板显示当前和可用社区版本、可选的纯文本发布摘要、签名状态，以及与当前系统和程序架构匹配的已验收 GitHub 安装包。用户明确点击后才交给系统浏览器下载；下载失败时可通过完整发布说明再次获取。

面板支持将本版提醒推迟 24 小时或忽略本版，后续版本仍可提醒。偏好以 schema version 1 存入 Electron userData 下的 `community-update-preferences.json`，首次使用时忽略与暂缓版本为 null，暂缓截止时间为零。文件损坏和写入失败会在面板中显示，不会谎报保存成功。手动检查仍可查看已暂缓或忽略的版本。`community/release.json` 提供完整社区版本号，并以 `dshCommunityVersion` 写入安装包；发布程序拒绝与安装包版本标识不一致的标签。版本排序先比较上游语义版本，再比较社区修订序号，包含预览版到正式版的升级。没有此提醒功能的旧安装包需要手动升级一次。找不到匹配安装包、检查失败与已是最新版本分别显示。`community/tests/update-panel.mjs` 验证提醒界面的可访问交互；安装后验收还会使用受控版本清单验证真实 preload/main IPC、明确点击打开浏览器、偏好保存及静默失败。更新验收不代表模型供应商的可用性。
